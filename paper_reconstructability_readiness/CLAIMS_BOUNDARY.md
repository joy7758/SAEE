## Supported claims

1. A perfect binary claim classifier exists over an evidence abstraction if
   and only if the semantic label is constant within every equivalence class
   induced by that abstraction.
2. If a complete valid package and a complete invalid package have the same
   field-presence vector, no presence-only classifier can classify both.
3. Across `k` matched positive/negative abstraction-equivalent pairs, every
   deterministic abstraction-only classifier makes at least `k` errors.
4. The 16 authored pairs preserve required-field vectors, JSON keys/types, and
   nominal outcomes while changing one semantic relation.
5. On this constructed dataset, field presence and key/type shape false-support
   16 negatives, affirmative-decision checks false-support 14, and the
   relation-aware evaluator false-supports 0.
6. Five local repetitions produce one canonical result hash, and the protected
   authority fields remain false in all 32 outputs.

## Definitions that travel with the claims

`bounded_reconstructability` is required-operand presence under one named
profile. It is not the eight-property Load-Bearing Evidence metric, executed
replay, causal identifiability, external trace fidelity, or general
auditability.

`relation_aware_profile_support` means only that a closed synthetic package
satisfies one file-backed profile. It is not external truth, authorization,
certification, or a production-readiness decision.

`false_support` is a positive rule output on an authored relation-invalid case.
It is not an observed field incident or population failure rate.
