# SAEE Kernel Recommendation

Generated: 2026-07-02

This is an analysis artifact, not a feature proposal or implementation plan.

## Collapse Analysis

Current system classification: **B) Partial evolution system**

Why:

- It is more than a static architecture system because AOP, POP, MVK, VAES,
  Agent Evidence, ARO-Audit, and Token Governor provide schemas, fixtures,
  verification, execution, receipts, and selection signals.
- It is not a full evolutionary system because no scanned repository closes the
  loop from sensing to trait extraction, genome branching, sandbox development,
  Pareto fitness, selection, lineage memory, rollback/dormancy, and next
  generation.
- The legacy `digital-biosphere-architecture` repository is architecture-dominant
  and explicitly not a runnable source map or implementation entry.

## Single Missing Kernel

Missing kernel: **SAEE Evolution Kernel Root**

Definition for this analysis: the single root state machine that binds
agent-readable traits, candidate genomes, sandbox runs, fitness records,
selection decisions, lineage events, dormancy, rollback, and next-generation
handoff into one generation ledger.

This kernel is missing as an integrated artifact. Its pieces exist across
subsystems, but the population-level loop does not.

## Evolution Kernel Root

Recommended root repository: **`.`**

Reason:

- `README.md` declares this repository as the Digital Biosphere Evolution Engine
  mainline and states that other repositories are subsystems.
- `AGENTS.md` defines SAEE as evolution-first and forbids reframing the project
  as an audit SDK or generic multi-agent workflow system.
- `agent-index.json` already names the canonical SAEE loop and subsystem
  directories.
- `PROJECT_STATUS.md` correctly preserves the boundary: local scaffold only,
  no completed implementation claim.

## Why No Scanned Legacy Repo Should Become Root

| Repository | Reason it should remain a subsystem |
| --- | --- |
| `digital-biosphere-architecture` | Static meaning and architecture hub; promoting it would keep SAEE architecture-dominant. |
| `execution-integrity-core` | Strong execution substrate, but too runtime/execution-centered to own sensing, trait extraction, population branching, and archive. |
| `agent-evidence` | Strong archive/evidence layer, but audit/evidence must remain immune/archive support, not project core. |
| `aro-audit` | Immune and receipt-validation layer, not the primary genome or evolution loop. |
| `token-governor` | Governance and selection-pressure layer, not mutation or lineage root. |
| `agent-object-protocol` | Genome-definition source for object traits, not a population runtime. |
| `persona-object-protocol` | Genome-definition source for persona traits, not a full kernel. |
| `fdo-kernel-mvk` | Execution-integrity proof substrate, not a closed-loop evolution engine. |

## Final Kernel Answer

The single missing kernel is the **SAEE Evolution Kernel Root**.

The root should be the current SAEE repository, not any of the eight scanned
legacy repositories. The eight repositories should be treated as genome sources,
execution substrates, governance/selection signal providers, archive layers, or
immune subsystems.
