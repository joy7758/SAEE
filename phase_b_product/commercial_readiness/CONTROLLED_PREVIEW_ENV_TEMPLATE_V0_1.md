# SAEE Controlled Preview Environment Template v0.1

Status: controlled-preview configuration template, not production deployment.

This document records the minimum local configuration shape for a controlled
SAEE preview environment. It is a commercial-readiness surface for safe pilot
setup. It does not deploy SAEE, publish a product, contact customers, configure
payment, claim production readiness, or expose private core.

## Template File

```text
saee_backend/config_examples/controlled_preview.env.example
```

The template contains placeholders only. It must be copied into a local,
git-ignored environment file and edited before any real preview session.

## Required Controlled-Preview Settings

```text
SAEE_ENV=preview
SAEE_ALLOWED_ORIGINS=https://preview.example.invalid
SAEE_REQUIRE_API_KEY=true
SAEE_API_KEY=replace-with-random-preview-key-min-32-chars
SAEE_REQUIRE_TENANT_ID=true
SAEE_ALLOWED_TENANT_IDS=preview-tenant-001
SAEE_STORAGE_BACKEND=sqlite
SAEE_REQUEST_AUDIT_ENABLED=true
SAEE_RETENTION_DAYS=30
SAEE_SUPPORT_CONTACT=replace-with-controlled-preview-support-mailbox-or-ticket-queue
SAEE_SECURITY_CONTACT=replace-with-controlled-preview-security-mailbox-or-ticket-queue
SAEE_PRODUCTION_SUPPORT_EVIDENCE_PATH=replace-with-local-production-support-evidence-json-path
SAEE_PRODUCTION_DATA_OPERATIONS_EVIDENCE_PATH=replace-with-local-production-data-operations-evidence-json-path
SAEE_PRODUCTION_OPERATIONS_EVIDENCE_PATH=replace-with-local-production-operations-evidence-json-path
SAEE_PRODUCTION_BILLING_REVENUE_EVIDENCE_PATH=replace-with-local-production-billing-revenue-evidence-json-path
SAEE_PRODUCTION_TENANT_STORAGE_EVIDENCE_PATH=replace-with-local-production-tenant-storage-evidence-json-path
SAEE_PRODUCTION_CUSTOMER_VALIDATION_EVIDENCE_PATH=replace-with-local-production-customer-validation-evidence-json-path
SAEE_RESTORE_DRILL_REPORT_PATH=replace-with-path-to-passing-RESTORE_DRILL_REPORT.json
SAEE_PRODUCTION_OIDC_ISSUER=replace-with-production-oidc-issuer-url
SAEE_PRODUCTION_OIDC_AUDIENCE=replace-with-production-oidc-audience
SAEE_PRODUCTION_OIDC_JWKS_URL=replace-with-production-oidc-jwks-url
SAEE_PRODUCTION_RBAC_POLICY_PATH=replace-with-local-rbac-policy-json-path
```

These settings are designed to satisfy the local commercial preflight rules for
controlled preview configuration:

- non-local environment selected;
- explicit non-wildcard CORS origin;
- API key guard enabled;
- tenant request boundary enabled;
- tenant allowlist configured;
- SQLite public-shell persistence selected;
- request metadata audit enabled;
- retention window configured;
- controlled-preview support intake contact configured;
- controlled-preview vulnerability intake contact configured;
- local production support / SLA evidence path configured for launch-gate
  review only;
- local production data-operations evidence path configured for restore-test
  and restore-policy launch-gate review only;
- local production operations evidence path configured for monitoring, alert
  delivery, and on-call launch-gate review only;
- local production auth evidence path configured for identity-provider,
  OAuth/OIDC, and RBAC launch-gate review only;
- local production privacy/security/legal evidence path configured for formal
  security review, privacy legal review, DPA, and vulnerability-management
  launch-gate review only;
- local production billing/revenue evidence path configured for pricing-page,
  payment-provider, invoice, tax, refund, and tenant-billing launch-gate
  review only;
- local production customer-validation evidence path configured for
  pilot-results and customer-validation launch-gate review only;
- passing isolated public-shell restore drill report path configured, including
  backup manifest size and SHA-256 integrity verification.
- optional future production-auth implementation inputs are placeholder-only.

`SAEE_RESTORE_DRILL_REPORT_PATH` must point to a local
`RESTORE_DRILL_REPORT.json` generated by the isolated restore drill. This is
controlled-preview evidence only. The referenced report must pass both
readability checks and backup manifest size/SHA-256 integrity checks. It does
not claim production restore testing or a production restore policy.

## Human Procedure

1. Copy `saee_backend/config_examples/controlled_preview.env.example` to a
   local file that is not committed.
2. Replace `SAEE_API_KEY` with a real random preview secret.
3. Replace `SAEE_ALLOWED_ORIGINS` with the actual controlled preview origin.
4. Replace `SAEE_ALLOWED_TENANT_IDS` with the approved preview tenant IDs.
5. Replace `SAEE_SUPPORT_CONTACT` with the approved preview support mailbox or
   ticket queue.
6. Replace `SAEE_SECURITY_CONTACT` with the approved preview security mailbox
   or ticket queue for vulnerability intake.
7. Replace `SAEE_PRODUCTION_SUPPORT_EVIDENCE_PATH` only if a local
   production-support evidence JSON has been reviewed. This does not publish an
   SLA or create production support.
8. Replace `SAEE_PRODUCTION_DATA_OPERATIONS_EVIDENCE_PATH` only if a local
   production restore-test and restore-policy evidence JSON has been reviewed.
   This does not run production restore or touch live data paths.
9. Run a local public-shell backup and isolated restore drill, then replace
   `SAEE_RESTORE_DRILL_REPORT_PATH` with the generated
   `RESTORE_DRILL_REPORT.json` path. The report must show that readability and
   backup manifest integrity checks passed.
10. Keep `SAEE_RETENTION_DRY_RUN=true` until a separate data-retention execution
   request is approved.
11. Run:

```bash
python3 scripts/saee_commercial_preflight.py
python3 scripts/saee_controlled_preview_env_template_smoke.py
```

## What This Does Not Provide

- production identity provider;
- OAuth/OIDC, SSO, or RBAC;
- tenant-isolated storage;
- tenant billing isolation;
- production restore testing or production restore policy;
- customer data processing approval;
- production monitoring or external alert delivery;
- full vulnerability management, remediation SLA, coordinated disclosure, or
  penetration testing;
- staffed customer support, production support, on-call, or SLA;
- published pricing, payment provider, checkout, or invoice operations;
- customer validation;
- production readiness.

## Commercial Readiness Role

This template closes a practical trial-readiness gap: a reviewer can see exactly
which environment variables are required before moving from localhost-only demo
to a controlled preview setup. It remains a configuration template and does not
authorize production use.
