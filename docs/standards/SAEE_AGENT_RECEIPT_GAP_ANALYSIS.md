# SAEE 智能体收据差距分析 v0.1

## 分析口径

本分析只比较任务给出的外部概念族与仓库现有 SAEE 对象，没有联网核对当前规范文本。因此“外部模型覆盖更好”表示该概念族在研究问题上更直接，不表示某个具体草案已经实现、通过或标准化了这些能力。

该分析保持 `production_ready=false`，不形成实现、采用、认证或发布状态。

## 1. SAEE 已经覆盖什么

- 资源解析收据区分请求资源、解析 URI、发布者声明、内容摘要、策略引用和沙盒边界。
- Evidence Adequacy Profile 区分证据存在、对象有效与对特定声明是否满足剖面。
- `AUTHORIZED_AGENT_ACTION` 检查 agent/action 引用、授权窗口、decision 与范围覆盖。
- `HUMAN_OVERSIGHT` 检查审批上下文、范围、时间和动作绑定。
- `EXECUTION_BOUNDARY` 检查资源、效果、摘要、URI、沙盒和因果引用的一致性。
- OpenTelemetry 风格映射只产生候选字段，不能自动成为证据。

这些都是本地、合成、离线能力，不证明外部身份、真实授权或现实事件发生。

## 2. 外部收据概念模型在哪些问题上更直接

从概念标签看，动作收据和审计轨迹路线通常更直接聚焦：

- 跨实现共享的 action identifier 或 action digest；
- 明确的动作收据序列化格式；
- 签名者、验证者和信任根角色；
- 收据组合、转交或跨主体验证；
- 面向互操作的字段语义和版本协商。

SAEE 当前没有实现这些外部协议面。尤其 `receipt_digest` 不是数字签名，`policy_decision_ref` 也不是授权真实性证明。

## 3. SAEE 增加了什么研究问题

外部收据概念主要描述动作或其授权／签名材料。SAEE 当前的独特研究重点是：

> External receipts describe actions. SAEE evaluates evidence sufficiency for accountability claims.

> 外部收据描述动作。SAEE评估证据是否足以支持责任声明。

这意味着 SAEE 不只问“是否有一份动作记录”，还问：

- 针对哪个 `claim_type`？
- 哪些字段是必需的？
- 哪些引用、范围、时间或因果关系必须成立？
- 缺少什么时应以哪个稳定原因码失败？
- 一个通过的本地剖面仍有哪些现实真实性边界？

这不是对外部收据模型的替代，而是一个可位于其后的 evidence adequacy（证据充分性）分析层。

## 4. 尚未解决的问题

- 没有核对或绑定任何外部规范版本、文档哈希或字段定义。
- 没有通用 action digest、外部 canonicalization 或签名验证协议。
- 没有跨组织身份、信任根、密钥轮换或撤销模型。
- 没有将外部人类授权凭据转换为已认证审批证据。
- 没有跨收据共享的组合标识或通用组合验证器。
- 没有隐私选择性披露、分离载荷或最小披露协议。
- 没有法律事实认定、责任分配或监管提交模型。
- 没有外部互操作测试、第三方实现测试或标准组织反馈。

## 研究与论文价值

本 crosswalk 可作为 related work（相关工作）素材，提出一个可检验的分层问题：

```text
动作描述层
    ↓
完整性／签名验证层
    ↓
证据关系组合层
    ↓
声明充分性评估层
    ↓
现实或法律事实认定（本项目未实现）
```

未来研究必须用具体、版本固定的外部文档和第三方实现重新验证本 crosswalk，不能把 v0.1 的本地分析当作标准贡献已经被接受。
