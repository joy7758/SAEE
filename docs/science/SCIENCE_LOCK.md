# SAEE Science Lock

## Status

SAEE is locked as a Computational Evolution Dynamics research program.

Science Lock means:

- no new v0.x upgrades;
- no new kernel design;
- no new runtime layer;
- no new evolution mechanics;
- no observer feedback into v1.0;
- no external validation claim;
- no universal law claim from local runs.

Allowed work is limited to:

1. describing observed evolution phenomena;
2. classifying evolution behavior;
3. extracting candidate laws from repeated observations;
4. positioning SAEE in existing academic literature without adding mechanics;
5. freezing the paper-facing scientific description before submission
   packaging;
6. documenting final layer authority without adding runtime or theory;
7. archiving local scientific closure and opening candidate universality
   analysis without claiming universal laws or external validation;
8. packaging the frozen scientific object into paper-facing interpretation
   surfaces without adding claims;
9. projecting the frozen paper interpretation into venue-specific paper
   skeletons without changing claims, experiments, laws, or runtime behavior;
10. repairing hostile-review defects in paper-facing representation without
    changing the frozen scientific object.

## Scientific Object

SAEE studies long-horizon behavior in computational populations driven by
replication, mutation, selection, and lineage preservation.

The locked research object is:

```text
population dynamics
mutation behavior
selection outcomes
lineage DAG
stability and collapse
regime formation
attractor emergence
candidate invariant laws
```

## Boundary

Science Lock is not a kernel upgrade and not a product release.

It does not claim:

- release;
- DOI;
- package upload;
- external publication;
- external scientific validation;
- universal evolution laws;
- production science;
- production deployment.
- manuscript submission;
- manuscript acceptance.
- reverse dependency from runtime or protocol layers into the frozen
  scientific object.
- validated universality theory.
- REDS-MO as externally validated class.
- official ALife template compliance.

## Agent Rule

Future agents must treat SAEE after this point as a research program around
Computational Evolution Dynamics. If a requested change adds mechanics or a new
runtime layer, create an evolution proposal instead of changing code.

For paper packaging, future agents must preserve the Submission Freeze:

- object name: `LCR-REDS Object`;
- submission-ready is not submitted;
- no new kernel, runtime, experiment, theory axiom, or evolution law;
- no external validation, universal theory, physical-law, or benchmark
  superiority claim.
- final architecture work must remain documentation-only and preserve
  `L1 -> L2 -> L3` dependency direction.
- scientific closure work must remain local, paper-facing, and
  documentation-only.
- universality work must stay hypothesis-only unless a separate evidence
  protocol is created and explicitly marked as a new empirical boundary.
- final interpretation work must remain paper-structuring only and must not
  imply submission, acceptance, publication, external validation, or universal
  law status.
- ALife formatting work must remain representation-only and must not imply
  official template compliance, submission, acceptance, publication, DOI,
  external validation, or new SAEE evidence.
- hostile-review repair work must remain paper-facing only and must not add
  theory, experiments, laws, kernels, runtime behavior, external validation,
  submission, acceptance, publication, release, or DOI status.
